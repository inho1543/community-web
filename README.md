# 캠퍼스광장 — AWS 커뮤니티 웹서비스

학과 행사 및 수강신청 등 특정 시기에 사용자가 집중될 수 있는 익명 커뮤니티 데모입니다.

## 주요 기능
- 게시글 작성 및 목록/상세 조회
- 댓글 작성
- 게시글 좋아요 / 취소 (브라우저별 임시 방문자 ID 기준)
- 데이터 유효성 검증 및 오류 응답

**주의:** 로그인/관리자 기능이 없는 과제용 데모입니다. 누구나 게시글을 작성할 수 있으므로 공개 장기 운영에 적합하지 않습니다.

## AWS 구성도

```text
사용자 브라우저 → EC2 퍼블릭 IPv4:8080 → Nginx 컨테이너 :80
                                         └─ /api/* → Flask(Gunicorn) :5000
                                                         └─ SQLite (Docker named volume)
```

AWS 서비스: EC2 1대. Docker Compose로 Nginx와 Flask를 실행합니다. SQLite는 Docker named volume에 보관하여 재배포 시 유지합니다.

ELB / Auto Scaling: 본 과제는 소규모 시연이므로 비용 및 운영 복잡도를 고려하여 적용하지 않았습니다. 이용자가 몰리는 학과 행사나 수강신청 기간에는 향후 요청 분산과 수평 확장을 검토할 수 있습니다. 단, **SQLite를 쓰는 현재 구조에서는 여러 서버의 데이터 공유가 불가능**하므로 로드 밸런서와 Auto Scaling 도입 전에 공유 DB 등으로 구조를 변경해야 합니다.

## 실행

필수: Docker 및 Docker Compose

```bash
docker compose up -d --build
docker compose ps
curl http://localhost:8080/api/health
```

접속: `http://<EC2의 퍼블릭 IPv4>:8080`

AWS 보안 그룹 **인바운드 TCP 8080**은 시연하는 접속 IP만 허용하는 것을 권장합니다. SSH(22)도 관리자 IP로 제한하세요. EC2 외부 IP가 바뀌면 접속 주소가 변경될 수 있습니다.

로그: `docker compose logs -f` / 중지: `docker compose down`

데이터 보호: `docker compose down -v`는 **데이터 볼륨까지 삭제**하므로 사용하지 마세요.

## 기능별 테스트 기록 (시연 후 실제 결과 작성)

| 기능 | 입력 | 기대 결과 | 실제 결과 |
|---|---|---|---|
| 글쓰기 정상 | 닉네임/제목/내용 입력 | 게시글 목록에 추가 | 미검증 |
| 글쓰기 실패 | 제목 공백 | 등록 거절 | 미검증 |
| 댓글 정상 | 닉네임/댓글 입력 | 해당 글의 댓글 목록에 추가 | 미검증 |
| 댓글 실패 | 댓글 공백 | 등록 거절 | 미검증 |
| 좋아요 정상 | 좋아요 클릭 | 좋아요 수 +1 | 미검증 |
| 좋아요 경계 | 동일 브라우저에서 다시 클릭 | 좋아요 취소 및 -1 | 미검증 |
| 데이터 유지 | 새로고침 및 컨테이너 재시작 | 글/댓글 유지 | 미검증 |

## 코드 위치와 요청 경로

- `frontend/index.html`, `style.css`, `script.js`: UI, 사용자 입력 처리, API 요청
- `nginx.conf`: 정적 페이지 제공 및 `/api/` 역방향 프록시
- `backend/app.py`: Flask API 및 SQLite SQL 처리
- `docker-compose.yml`: 컨테이너 네트워크/볼륨/포트 구성
